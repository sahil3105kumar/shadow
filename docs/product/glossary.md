# Glossary

This document defines the official terminology used throughout the Shadow project.

Every document, design discussion, Architecture Decision Record (ADR), and implementation should use these definitions consistently.

---

# A

## Action

A validated request to perform an operation in the external world.

Examples include opening an application, sending an email, moving a window, executing an API request, or controlling a smart device.

Actions never perform reasoning—they only execute approved tasks.

---

## Action Layer

The subsystem responsible for interacting with the outside world.

It receives validated execution requests from Cognition and performs them using appropriate connectors or integrations.

---

# C

## Cognition

The intelligence layer of Shadow.

Cognition transforms information into understanding by combining reasoning, memory, planning, context retrieval, and decision support.

It answers:

> **"What does this mean?"**

---

## Context

The collection of information relevant to a specific interaction.

Context may include memories, conversations, projects, documents, calendar events, current tasks, preferences, and environmental information.

Context is assembled dynamically rather than stored permanently.

---

# D

## Domain

A major subsystem with a well-defined responsibility.

Examples include:

* Kernel
* Perception
* Cognition
* Action
* Infrastructure

Domains communicate exclusively through events.

---

# E

## Event

The fundamental unit of communication inside Shadow.

An Event is an immutable message describing something that has already happened.

Examples:

* `persona.message.received`
* `memory.created`
* `screen.changed`
* `action.completed`

Events are published through the Event Bus.

---

## Event Bus

The communication backbone of Shadow.

The Event Bus routes events between independent domains while managing prioritization, backpressure, retries, and delivery guarantees.

---

# I

## Infrastructure

The collection of services supporting the platform.

Examples include storage, networking, authentication, encryption, synchronization, monitoring, scheduling, and deployment.

Infrastructure provides capabilities but contains no business logic.

---

# K

## Kernel

The deterministic core of Shadow.

The Kernel coordinates every subsystem while remaining completely domain-blind.

Its responsibilities include:

* Scheduling
* Event routing
* Resource management
* Lifecycle management
* Configuration
* Security
* Plugin loading
* Fault recovery

The Kernel never performs AI inference or business logic.

---

## Knowledge Graph

A structured representation of entities and their relationships.

Unlike vector search, the Knowledge Graph captures explicit connections such as people, projects, organizations, documents, and events.

---

## Knowledge Node

A single entity within the Knowledge Graph.

Examples include:

* A person
* A document
* A project
* A company
* A concept

Nodes are connected through typed relationships.

---

# L

## Lifecycle Manager

A Kernel component responsible for starting, stopping, monitoring, and recovering system services.

---

# M

## Memory

Information intentionally preserved by the user or generated by Shadow for future retrieval.

Memory represents long-term knowledge rather than temporary conversational context.

---

## Memory Store

The persistent storage layer responsible for maintaining memories across sessions.

---

## Modality

A type of information that Shadow can perceive.

Examples include:

* Text
* Speech
* Images
* Video
* Documents
* Screen content

The system should remain extensible to future modalities.

---

# P

## Perception

The subsystem responsible for observing and interpreting external inputs.

Perception transforms raw information into structured events.

It answers:

> **"What happened?"**

Perception never performs planning or decision-making.

---

## Persona

The conversational identity through which users interact with Shadow.

A Persona defines characteristics such as:

* Name
* Voice
* Personality
* Communication style
* Appearance (where applicable)

The default Persona is **Mahoraga**, but users may customize or replace it without affecting the underlying platform.

---

## Plugin

An independently deployable extension that adds new capabilities to Shadow.

Plugins communicate with the system through well-defined interfaces and events rather than direct integration.

---

# R

## Reasoning

The process of analyzing information, retrieving context, evaluating alternatives, and generating conclusions.

Reasoning belongs exclusively to the Cognition domain.

---

## Resource Manager

A Kernel component responsible for allocating and scheduling computational resources.

Examples include CPU, memory, GPU, VRAM, model context windows, and background task priorities.

---

# S

## Scheduler

A Kernel service responsible for coordinating asynchronous tasks, prioritizing workloads, and managing execution timing.

---

## Semantic Memory

Knowledge stored according to meaning rather than exact wording.

Semantic Memory enables users to retrieve information using natural language instead of keywords or filenames.

---

## Shadow

The Cognitive Operating System itself.

Shadow is the platform responsible for coordinating perception, cognition, action, and infrastructure.

Shadow is not a chatbot or AI model.

---

## Shadow Kernel

The deterministic runtime responsible for coordinating every subsystem within Shadow.

It provides the operating environment upon which all higher-level domains depend.

---

# T

## Task

A unit of work requested by the user, generated by Cognition, or scheduled by the system.

Tasks may produce one or more events during execution.

---

# U

## User

The individual who owns and controls a Shadow installation.

The initial architecture assumes a single-user system while remaining extensible to future multi-user environments.

---

# V

## Vector Store

A database optimized for semantic similarity search using vector embeddings.

Vector Stores complement—but do not replace—the Knowledge Graph.

---

# W

## Workspace

A logical grouping of memories, documents, projects, tasks, and knowledge related to a common objective.

A Workspace provides organizational structure without isolating information from the broader knowledge graph.

---

# Guiding Terminology

Throughout the project, the following language should be used consistently:

| Preferred Term  | Avoid                   |
| --------------- | ----------------------- |
| Shadow          | AI Assistant, Bot       |
| Persona         | Character, Avatar       |
| Cognition       | AI Engine, Brain Module |
| Perception      | Input Handler           |
| Action          | Automation Engine       |
| Event           | Message, Signal         |
| Memory          | Chat History            |
| Knowledge Graph | Database                |
| Workspace       | Folder, Collection      |
| Kernel          | Core Engine             |

Using consistent terminology keeps the architecture, documentation, and implementation aligned as the project evolves.
